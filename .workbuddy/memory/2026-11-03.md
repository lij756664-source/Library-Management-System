# 2026-11-03

## 修复「图书详情」预约排队人数与列表不一致

- 现象：图书检索列表显示《骆驼祥子》预约排队 3 人，点开详情弹窗显示 0 人。
- 根因：`BookMapper.xml` 中 `findAll` 用子查询统计了 `waitingCount`（WAITING+READY），
  但 `findById`（详情接口 `/api/books/{id}` 走它）**完全没有查这个字段**，返回 null，
  前端 `detail.waitingCount || 0` 兜底成 0 人。
- 修复：
  1. `BookMapper.xml`：抽出 `<sql id="waitingCountExpr">` 片段，`findAll` 与 `findById` 共用，口径统一。
  2. `BookBrowse.vue`：详情行改为 `waitingCount > 0 ? 'N 人' : '暂无排队'`，与列表展示一致。
- 验证：数据库 book_db 中 id=9 骆驼祥子 stock=0，reservation 有 3 条 WAITING；
  按修复后的详情 SQL 查询返回 waitingCount=3。8080 端口后端需重启（重新编译）才生效。

### 关于「暂无排队」的说明（同一问题的中间状态）
- 前端 Vite 热更新立即生效，改完文案就地变成了「暂无排队」；
- 但 MyBatis 的 mapper XML 只在应用启动时解析，运行中的 JVM 仍是旧语句，
  实测 `GET /api/books/9` 仍返回 `waitingCount: null`，而 `GET /api/books?keyword=骆驼` 返回 3；
- 项目未引入 spring-boot-devtools，改 XML 必须重启后端（IDE 里 Rerun / 重新运行）。

### 补充：前端兜底（同一问题第三次反馈后追加）
- 用户只刷新了浏览器，后端进程 PID 未变（仍是 31564），`GET /api/books/9` 依然 `waitingCount: null`；
- 在 `BookBrowse.vue` 的 `openDetail` 中加兜底：详情接口返回的 `waitingCount` 为 null 时，
  沿用列表行数据里的实时值，保证「列表 3 人 / 详情 3 人」两个入口一致，且不依赖后端是否重启；
- 后端修复（BookMapper.xml 共用 waitingCountExpr 片段）仍保留，重启后该兜底自动空转。
