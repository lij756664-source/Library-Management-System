## 八、并发测试：与借还、预约负责人联合执行

### 执行方法

- 每轮先记录前置数据库状态、令牌所属用户、请求参数，再通过并发工具同时发出两个请求。
- 可使用支持并行的测试工具；普通手动连续点击、Postman串行Runner不能作为并发证据。
- 两个并行HTTP请求只是基础，需保存客户端起止时间及服务端日志，确认业务处理重叠。不能确认重叠时记“未验证并发”，不记通过。
- 每个场景至少重建前置数据并重复5轮；无失败只代表已测轮次，不证明所有调度都安全。必要时负责人在测试环境加可控断点/屏障，稳定制造重叠。
- 改规则重叠用例需覆盖“先读规则后保存”和“先提交规则后读取”。一次读取整组规则不能要求所有进行中的借阅立即切换为最新版。

### 简单并行请求参考（可选）

可在Node 18+的独立本地脚本中使用下列结构，TOKEN先由执行人安全提供，不写入提交文件或测试证据。按具体场景修改两个URL、method和body；执行的是实际写请求，只对确认的测试夹具运行。

```javascript
const base = 'http://127.0.0.1:8080/api';
const token = process.env.TEST_TOKEN;
if (!token) throw new Error('请在当前终端提供 TEST_TOKEN');
const ids = [process.env.TEST_BOOK_ID_1, process.env.TEST_BOOK_ID_2].map(Number);
if (!ids.every(id => Number.isInteger(id) && id > 0)) {
  throw new Error('请在当前终端提供测试图书 TEST_BOOK_ID_1、TEST_BOOK_ID_2');
}
const specs = ids.map(bookId => ({
  path: '/borrows', method: 'POST', body: { bookId }
}));
await Promise.all(specs.map(async (spec, index) => {
  const begin = new Date().toISOString();
  const response = await fetch(base + spec.path, {
    method: spec.method,
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: spec.body ? JSON.stringify(spec.body) : undefined
  });
  console.log({ index, begin, end: new Date().toISOString(),
    http: response.status, result: await response.json() });
}));
```

将示例保存为本地 .mjs 文件，在当前终端提供 TEST_TOKEN、TEST_BOOK_ID_1、TEST_BOOK_ID_2 后才能运行；不要把令牌写入脚本。此示例仅覆盖同用户的两次借阅，跨用户场景需分别提供各自令牌。运行前确认ID，运行后核对数据库；不要把相近的客户端开始时间当作服务端事务重叠的唯一证据。

P01：先记录数据规模（图书、类别、借阅记录数及时间跨度）；统计页面预热1次，再对“全部历史”和一个固定日期范围各测10次，从点击到图表/表格更新完成计时，保留每次值及最大值。若沿用原测试计划的3秒目标，必须先确认相同数据规模和环境；未确认时只登记实测值，不自行宣布性能达标。旧版本性能结果不可直接沿用。

结束时确认：恢复测试前规则（不一定是A，以原始记录为准）；撤销故障注入和调试断点；保留失败夹具及证据；清理自己本轮创建的数据或恢复测试库备份，不按宽泛条件删除其他组员数据。若需复现失败，先保留证据再清理。
