# 剩余自动化测试结果

执行日期：2026-11-01。此次继续测试，没有修复应用功能或界面。测试脚本、日期计算测试和独立数据夹具属于验收辅助文件。

## 本轮结论

| 项目 | 结果与证据 |
|---|---|
| 指定规模统计页面性能 | 5种范围各5次，25次均低于3秒；页面排行/分类数据逐条匹配独立预期，无请求失败，加载遮罩已消失 |
| 保存成功但响应丢失 | 后端提交31天，代理扣留成功响应，浏览器10秒超时；页面提示尚未确认并重查，最终展示有效31天 |
| 保存请求未提交 | 输入32天，请求未送到后端，浏览器超时；重新查询有效值仍31天，未把输入误显示为有效配置 |
| 保存成功且核实查询失败 | 后端提交33天，丢弃响应且核实请求失败；页面保持尚未确认；恢复连接手动重查，展示实际33天 |
| 签名正确但已过期的令牌 | 规则、统计、本人借阅接口均401，无受保护数据返回 |
| 逾期/已还直接请求 | 逾期续借、已还续借、重复归还均拒绝；日期、次数、金额、状态未变 |
| 改规则与预约取书重叠 | 观察到2个服务端锁等待请求，取书取得完整旧规则组3/2/7/0.50且应还日期一致，没有混组 |
| 同名不同图书ID与多册汇总 | 专用2023年1月夹具：同一ID三名读者分别贡献1、2、3次，汇总6；另一同名不同ID为2，分别返回，不按书名合并 |
| 北京时间自然日计算 | 自动测试覆盖北京10日23:59为0、11日00:01为0.50、12日1.00、13日1.50及零日费逾期仍2天 |

超时行为通过，但提示存在可用性缺陷：全局同时弹出英文timeout of 10000ms exceeded和Network Error，应在统一界面修改时改成一致的中文反馈。不能把“行为正确”记作“所有提示已合格”。

测量从真实查询按钮点击开始，等待统计请求结束、Vue更新、至少两帧绘制机会以及加载遮罩透明/消失，再读取已渲染表格并计时。每次与生成数据时独立计算的排行和分类预期比较；不是接口耗时。

首次诊断616.6ms时已显示数据但探针未等待遮罩结束，原记录保存在“性能计时探针首轮诊断.json”，不作为完整显示耗时通过证据。修正测试探针后，首次挂载691.9ms也保留在原始记录，另做上述25次显式点击。没有以平均数代替逐次判定。正式材料若必须单独验收完全未预热的首次统计完整耗时，需要再启动干净实例补首轮记录；不能将不完整的首轮诊断直接宣称完整通过。

环境CPU、内存、OS、Node等见“性能测试结果.json”。浏览器为Codex内置Chromium，精确版本尚未获取；正式交付前补填。当前结果只代表本机这轮测试，不代表所有部署环境或多人并发也满足3秒。
