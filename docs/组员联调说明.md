## 先检查本机数据库

库名不必相同，但表和字段必须匹配。先复制application-local.example.yml为application-local.yml，填自己的库名、用户名和密码；local文件不提交。启动时使用local profile，JDK17。

| 你的情况 | 操作 |
|---|---|
| 新建空库，不需原数据 | 核对脚本中CREATE DATABASE/USE的库名后，依次执行database.sql、user_permission.sql、avatar.sql；不再执行快照迁移。新库无需reservation.sql补丁 |
| 原版结构且要保留原数据 | 停应用并备份；确认已具备原有权限/头像/预约结构、五项配置完整合法；执行migrations/001_rule_snapshots.sql一次 |
| 自己改过字段或已有快照 | 先导出结构对照，不盲目运行上述脚本；单独制定迁移 |

database.sql会删除表，只适用于指定的新建空库；user_permission.sql也含清理其新增表的语句，不能当作无损通用升级脚本。迁移DDL隐式提交，失败时先检查结构，不直接重跑。快照迁移使用当前选中的数据库，执行前确认USE目标。

旧记录先按升级前配置补四项快照，已还金额保留，再将当前配置重置为30/2/7/0.50/5。此为旧记录的兼容约定，不能声称恢复了未知历史规则。本人的book_db_current已经初始化完成，不能再次套迁移。

## 接口约定

使用现有Authorization: Bearer令牌及Result结构。需要同时看HTTP状态和响应体code；拒绝不能返回受保护信息。

| 接口 | 权限 | 用途 |
|---|---|---|
| GET /api/rules | ADMIN | 编辑页面读取五项有效规则 |
| PUT /api/rules | ADMIN | 五项必填、整组更新；字段见下表 |
| GET /api/rules/latest | ADMIN、USER | 最新五项规则只读入口，不提供修改 |
| GET /api/statistics/overview?start=YYYY-MM-DD&end=YYYY-MM-DD | ADMIN | 同一范围的categoryStats和topBooks；附dashboard整体概况 |
| GET /api/borrows/my | 当前登录人 | 从登录身份确定本人，传userId不能指定他人 |
| GET /api/borrows | ADMIN | 借阅管理及罚金核对 |

| 五项键名 | 默认 | 可设范围 |
|---|---:|---|
| borrow_days | 30 | 整数1—90 |
| max_renew_count | 2 | 整数0—5；0禁续借 |
| renew_days | 7 | 整数1—30；禁续借仍必填 |
| fine_per_day | 0.50 | 0—5.00，最多两位小数；0仍判逾期 |
| max_borrow_count | 5 | 整数1—10；0不合法 |

当前规则值以字符串返回，保存请求可以沿用字符串，避免金额精度被前端静默处理。页面已中文校验，服务端仍作完整校验。

两个日期都不填为全部历史；只填一个或倒置必须拒绝。按北京时间成功借出日期含首尾全天；排行次数降序、同次book.id数值升序、最多10条、排除零次；分类按当前类别汇总，保留零值类别。续借不增次数，归还不减次数。

兼容入口/statistics/category与/top-books不带上述日期范围，不能让它们代替新页面的同范围overview；dashboard卡片不随筛选范围变化。不要混用这两类入口导致范围不一致。

## 借还与预约负责人重点看

- 新借出和预约取书都写borrow_days_snapshot、max_renew_count_snapshot、renew_days_snapshot、fine_per_day_snapshot；不能只改普通借出入口。
- 旧借阅续借使用自身次数上限和续借天数，罚金使用原日费；数量上限每次新增借出/取书检查最新值。降限不改旧应还日期，不额外罚款，也不额外禁续借。
- FineService.calculate接收应还日期、原日费和明确计算日期；返回逾期天数与两位小数金额。纯计算方法不查库、不读当前时钟、不更新状态。
- 归还Service确定一次实际时间，计算并同事务保存状态、归还时间、最终逾期天数和金额，再完成必要库存/预约流转；任何必要步骤失败整体回滚。
- 未还查询动态暂计，不保存为最终金额；已还读取最终字段。最终不表示已缴费。
- RuleService.lock仅在外层事务内用于统一锁顺序，不能当作普通HTTP查询接口；规则保存/借出/取书/续借/归还先锁同一组配置行。串行等待是本期取舍，不承诺高并发吞吐。
- 返回字段finePerDaySnapshot、overdueDays、fineAmount、status、dueTime、returnTime用于展示。已还记录不再显示剩余日期；前端不另用最新日费重算旧记录。

## 建议联合验证顺序

1. 各自隔离开发分支和测试库，启动成功，核对角色入口与配置。
2. A规则借一本→改B规则→再借一本→分别续借，比较快照、日期和次数。
3. 零日费逾期、到期当天续借、归还最终金额固定；错误时状态/库存不部分提交。
4. 预约待取书→满额取书拒绝→归还释放→取书成功，核对快照和库存。
5. 借出/续借/归还/再借统计贡献1/1/1/2；类别移动和日期首尾边界。
6. 最后名额竞争、最后续借机会、重复归还、改规则与普通借出/取书重叠。不能把串行点两次当并发证据。
7. 管理员、读者本人/他人、匿名、失效令牌及直接请求权限。
