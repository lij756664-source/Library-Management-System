# D05 非法日期输入处理修复与复测

日期：2026-11-03。范围：统计接口日期参数异常处理。

## 问题与修复

原先请求 `/api/statistics/overview?start=bad&end=bad` 返回HTTP200、业务code=500，提示服务器内部错误。原因是Spring在进入Controller前转换LocalDate失败，异常落入全局500兜底。

在GlobalExceptionHandler中增加MethodArgumentTypeMismatchException专用处理。LocalDate转换失败现在返回业务code=400，提示“日期格式不正确，请使用年-月-日，例如2026-11-03”，data为空。HTTP状态沿用项目现有HTTP200加业务code约定。其他参数类型转换失败使用通用中文参数错误提示，不回显原始输入或异常内容。

## 实际执行验证

使用JDK17、预加载本机Byte Buddy agent执行离线Maven全套测试：33项，零失败、零错误、零跳过，BUILD SUCCESS。

新增StatisticsDateInputTest通过MockMvc走真实Spring MVC参数转换和异常处理：

| 请求start / end | 预期 | 结果 |
|---|---|---|
| bad / bad | 业务400、中文日期提示、空data；不调用统计服务 | 通过 |
| bad / 2026-11-03 | 同上 | 通过 |
| 2026-11-03 / bad | 同上 | 通过 |
| 2026-02-29 / 2026-03-01 | 非闰年2月29日拒绝，同上 | 通过 |
| 2026-11-03 / 2026-11-31 | 不存在日期拒绝，同上 | 通过 |
| 2024-02-29 / 2024-03-01 | 合法闰年日期正确传入统计服务，业务200 | 通过 |
| 不传日期 | null/null传入统计服务，业务200 | 通过 |

新增2个JUnit测试方法分别包含5个非法输入子场景和2个合法查询子场景。33项为JUnit方法数，与首轮参数化接口用例144项口径不同，不合并计数。

本次复测属于MVC集成边界和全套自动化测试，没有重新查询真实数据库统计，也没有把未重启的8080服务冒称已加载新代码。用户终端运行的后端需要重启，新处理才在该服务生效。统计Service及SQL未修改。
